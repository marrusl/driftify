# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **requirements.txt beside the pip venvs** — `/opt/myapp/requirements.txt` (minimal) and `/opt/legacy-app/requirements.txt` (standard) are generated from `pip freeze --local`, with a static pinned fallback. inspectah rates a venv high confidence only when a manifest sits beside it, so without these files no fixture ever produced a high-confidence venv.
- **Legacy-app venv at `/opt/legacy-app/venv`** (standard) — `--system-site-packages` paired with a requirements.txt and pure-Python packages, covering the system-site-packages flag at high confidence and with no C extensions. The kitchen-sink `/opt/shared-venv` continues to cover the same flag at medium confidence.
- **Venv at `/apps/reporting/venv`** (minimal) — sits outside every default scan root, so it is only detected when the scan is run with `--scan-path /apps/reporting`.
- **nginx on port 8081 with an `http_port_t` label** (standard): the managed nginx server block listens on 8081 instead of 8080, `semanage port -a -t http_port_t -p tcp 8081` labels the port, and firewalld opens 8081/tcp. This replaces the custom SELinux port label the removed sshd port move used to provide, on a package the profile already configures, so inspectah still has a port label to detect and render as a `semanage port` line.
- **systemd unit state beyond `.service` enablement**: the Services section now plants unit state that inspectah's unit model has to carry. minimal masks `tmp.mount` and enables `getty@tty2.service`. standard adds a local static unit linked by hand into `multi-user.target.wants/`, a local `Also=` pair, and `cockpit.socket` set against its preset, which is read at run time (enabled on RHEL 9, disabled on RHEL 10). kitchen-sink adds `cups.service`, `iscsid.service` and `virtnetworkd.service` enabled with their sockets disabled, `wg-quick@wg0.service` with a generated throwaway key in `/etc/wireguard/wg0.conf`, `multipathd.socket` enabled through `Also=`, a local unit with `UpheldBy=multi-user.target`, and `graphical.target` as the default target. The RPM section installs the packages these need. Each case sets a fixed end state, so the fleet test's profile sequence and any re-run leave it unchanged. A case that cannot be planted, such as `multipathd.socket` on RHEL 10 (no `[Install]`) or `UpheldBy=` on RHEL 9 (systemd 252), is skipped with a warning, and the completion summary lists every case as it turned out, with its unit, state and link path, or as skipped with the reason.
- **`StateDirectory=myapp` in `/usr/lib/systemd/system/myapp.service`** (standard) — gives `/var/lib/myapp` a declarative backing, exercising the StateDirectory class of inspectah's /var backing classification.

### Changed

- **`run-fleet-test.sh` scans beyond the default roots** — each scan now passes `--scan-path /apps/reporting` and `--scan-home appuser`, without which the new `/apps` venv and the existing appuser home environments never reach the fleet tarballs.

### Removed

- **`--undo` and `--undo-first`**: both flags are gone, along with every undo routine behind them, and `run-fleet-test.sh` drops `--no-undo` and no longer runs undo at startup. Undo reversed what driftify remembered doing, not what the host became, so it could leave a host that looked clean while still carrying drift: on RHEL 9 it restored none of the directive-edited configs (a same-version reinstall keeps `%config(noreplace)` files), removed a package the host had before the run, and set the timezone to UTC rather than back to the original. Revert the VM snapshot instead; driftify targets throwaway VMs, and a snapshot is the only restore that cannot leave drift behind.
- **sshd port move** (standard, kitchen-sink): driftify no longer sets `Port 2222` or `Port 2200` in `/etc/ssh/sshd_config`, opens those ports in firewalld, or adds an `ssh_port_t` SELinux label for them. The port move gave inspectah nothing to detect that the other sshd_config directives do not, and on a host that was not reverted it left sshd off port 22, so every ssh connection was refused. `PermitRootLogin no` (standard) remains.
- **sshd cipher, MAC, and kex overrides** (kitchen-sink): driftify no longer writes `Ciphers`, `MACs`, or `KexAlgorithms` to `/etc/ssh/sshd_config`. On RHEL 9 the stock `sshd_config.d/50-redhat.conf` includes the crypto-policies back end, which sets all three before the main file is read, so the lines never took effect. The kitchen-sink profile still produces a cross-profile variant of other configs, such as `chrony.conf` and `nsswitch.conf`.

### Fixed

- **`PermitRootLogin no` had no effect on hosts with an installer drop-in** (standard): driftify now also writes `PermitRootLogin no` to `/etc/ssh/sshd_config.d/00-driftify.conf` (mode 0600, like the stock drop-ins), alongside the existing `sshd_config` edit. The stock RHEL 9 `sshd_config` includes `sshd_config.d/*.conf` before its own directives and sshd keeps the first value it reads, so where the installer wrote `01-permitrootlogin.conf` with `PermitRootLogin yes`, `sshd -T` still reported `yes` while the summary said root login was set to no. The drop-in sorts first, so sshd enforces `no` from its next restart, and inspectah sees it as a new unowned config file in `sshd_config.d`.
- **nginx server block lands outside `http {}`**: driftify now inserts its managed `server` block into `/etc/nginx/nginx.conf` just before the `http` block's closing brace, and skips it with a warning if it cannot find that brace. It used to append the block after the `http` block, where `nginx -t` rejects it with `"server" directive is not allowed here`, so a drifted host had nginx enabled but unable to start. The minimal profile's block also moves from port 8080, which httpd's drifted `Listen 8080` already claims, to port 81, which is in the stock `http_port_t` set and so still needs no SELinux label.
- **Directive edits replace a commented example instead of the live line**: driftify now changes only live (uncommented) directives in RPM-owned configs and appends the directive when no live line exists, leaving commented examples as they were. It used to replace the first match commented or not, so in `httpd.conf` the example `#Listen 12.34.56.78:80` became `Listen 8080` while the real `Listen 80` stayed, and httpd took port 80 away from nginx's stock server. In `sshd_config`, `PermitRootLogin no` is now appended rather than written over the commented default.
